# Security model for the TRMNL feed and Planets

Status: active. It covers the features accepted in [ADR 0016](adr/0016-trmnl-display-feed.md) and [ADR 0017](adr/0017-planets-declarative-plugins.md), and the notification webhooks of [ADR 0020](adr/0020-notifications.md) (rows 12 to 17; row 11 covers the Home Assistant connections of [ADR 0019](adr/0019-connections-and-home-assistant.md)).

## Gate

No pull request that touches feed routes, notification routes or `planets/` merges without the mitigation and the test for its row below. A row's test is named here before the code exists, so a reviewer can check the PR against it. When a test lands, replace "planned" with its path.

## Assets and actors

- **Assets.** Household data (calendar, lists, budget), Planet secrets in the `SecretStore`, session cookies, and the host's LAN and cloud metadata endpoints.
- **Webhook receiver.** Whatever the owner points a notification at. It sees the household news the owner chose, and with the signing secret it can check a message came from this Orbit.
- **Feed token holder.** Anyone who has the token: the TRMNL cloud, the owner, and anyone the token leaks to. Read-only, one feed.
- **Planet author.** Untrusted. Controls the manifest and templates, nothing else.
- **Administrator.** Trusted. Installs Planets, approves permissions and egress hosts.
- **Anonymous internet client.** Can reach the public feed endpoint if the instance is exposed over HTTPS.

## Residual risks

- **Third-party rendering.** Feed content passes through TRMNL's cloud. The owner is told before creating a feed. Orbit cannot control what TRMNL does with it.
- **Public exposure.** The feed requires an instance reachable over HTTPS. That widens the attack surface of the whole instance, not only the feed route. The deployment docs must say so.
- **Token in a TRMNL plugin.** The token lives in the owner's plugin settings on TRMNL. Revocation is the only recovery.
- **Calendar links and event titles.** An ICS address is a credential. Orbit stores it encrypted, never returns or logs it, and the feed publishes only titles and times of the calendar fields an owner chose ([calendar guide](../operations/calendar.md)). Those titles still pass through TRMNL's cloud. Tests: `packages/testing/src/calendar.test.ts`, `apps/api/src/calendar.http.test.ts` (the address never appears in any response or the OpenAPI document).
- **Administrator approval.** A careless administrator can approve a broad permission. The install screen lists every permission to make that visible.
