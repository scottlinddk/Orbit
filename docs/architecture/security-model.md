# Security model for display feeds and Planets

Status: proposed. This document is a release gate for the TRMNL feed and Tier 0 Planets, not a claim that those features are implemented. ADR 0016 and ADR 0017 remain proposals. Before either feature ships, each applicable row below needs an implementation and a passing test. Calendar connectors must use the same outbound request guard as Planets (ADR 0003).

## Trust boundaries

- A household owner may configure a feed. An instance administrator installs a Planet from a local folder. Other members and anonymous callers must not gain either power through a feed token.
- A feed token is a bearer credential for **one read-only feed**, never a session or a general household credential. It travels in a request header, not a URL. Only its SHA-256 hash is stored, and the clear token is shown once. An owner can list and revoke feeds without retrieving their tokens.
- A Planet manifest, template, remote response, and ICS feed are untrusted input. Tier 0 templates receive only explicitly selected data and have no filesystem, process, network, or secret access.
- Outbound requests cross from the Orbit server into an operator-selected network. They must use one shared guard; a manifest's host permission alone cannot authorize access to the LAN.
- Stored integration credentials are available only to the connector making an authorized outgoing request. They are never put in a template context, response, diagnostic message, or log.

## Threats, controls, and test gates

The paths in the last column identify tests to add alongside the feature. Existing invitation tests show the current token and household-isolation patterns; they do not validate the future feed.

## Review gate

Review this model before merging feed routes or a `planets/` runtime. Every row relevant to that change needs a linked, passing test in the PR. Feed routes must appear in both the household isolation kit and the HTTP isolation suite. ADR 0016 and ADR 0017 must be accepted before their gated implementation issues proceed. The TRMNL feed requires a publicly reachable HTTPS Orbit instance and sends selected data through TRMNL's cloud; a LAN-only instance cannot use it.

The Home Assistant/HACS security incidents mentioned in the research are not cited here because their dates and details have not been verified against primary sources. This model is written for Orbit and does not reuse another project's text.
